- 板卡版本：扩展底板 v1.0
- 测试日期：2026-08-31
- 烧录环境：Windows，tyutool v3.2.9 @ 460800
- 监视：UART0 @ 115200（扩展板 CH340C = COM6）
- 测试顺序依据：`TEST_PLAN.md`；逐步详录见 `TEST_RESULTS.md`

## 二、各步骤要点

### Step 1 uart_loopback（通过）
- 发送方向（设备→PC）：`status:"alive"` 心跳每 2000ms 一条，`uptime_ms` 稳定 +2000 递增。
- 接收方向（PC→设备）：发送 `hello，你好`，设备原样回传（含中文 UTF-8 多字节），确认字节级回环。
- 回环为纯字节透传，**对发送内容无格式要求**（不必是 JSON、不必带换行）。

### Step 2 key1_uart（通过）
- 心跳稳定，12 组按下/抬起配对，序号 1–24 严格递增无丢帧。
- 去抖有效：每次按压仅一次 down + 一次 up；`held_ms` 物理合理（短按 90–175ms，长按至 5450ms）。

### Step 3 input_scan（通过）
- 5 机械键（k1–k5）+ 5 方向（上/下/左/右/中）全部 down/up 成对、ID 正确。
- 无空闲抖动：静止时只有心跳。
- 并发/交叠按压处理正确（各输入独立状态机，无串扰）。

### Step 4 lcd_st7789（通过，修复接线后）
- 现象：屏亮但恒定全白，不跟随固件 2 秒图案循环。
- 定位：固件侧 `ready` 与每帧 `result:0` 均正常，说明 SPI 数据在推送，故障在 SPI 数据路径/FPC。
- 根因：**FPC1 底层封装脚序镜像（Pin1↔Pin18）**，底层放置未做脚序镜像；网表逻辑正确。
- v1.0 处理：**排线反向插入**，两次镜像抵消，屏显示正常。
- 附带确认：该屏正式固件初始化需 **ST7789 INVOFF**（默认序列结尾 INVON 会全屏反色）。

### Step 6 LED4/LED5 指示灯（通过）
- 纯硬件目检，不涉及固件与 GPIO。接线：
  - LED4：`VBUS → R6 → LED4 → GND`（Type-C 5V 供电指示）
  - LED5：`BAT_P → R10 → LED5 → GND`（电池供电指示）
- 四种上电组合真值表全部吻合，两灯相互独立。

| 状态 | LED4 (VBUS) | LED5 (BAT) |
|------|-------------|------------|
| 全断电（Type-C 拔、电池开关关） | 灭 | 灭 |
| 仅插 Type-C（电池开关关） | 亮 | 灭 |
| 仅开电池开关（Type-C 拔） | 灭 | 亮 |
| Type-C + 电池开关都开 | 亮 | 亮 |

### Step 7 电池/开关（通过）
- 拨动开关 SW1（SK12D07VG5）串在电池 BAT+ 路径：切换时 LED5 随之亮灭，证明开关控制电池路径。
- Type-C 行为符合原理图：VBUS 仅经 LDO 供 CH340C，不供系统主电；仅插 Type-C 时 LED4 亮、串口桥可枚举。
- 全程仅接一节电池（并联会互相倒灌，不安全）。

### Step 8 wireless_selftest（通过）
- Wi-Fi 扫描（仅 2.4GHz）：多条 `scan_ok`，`ap_count` 13–28，`best_rssi` −47～−56 dBm（信号强），无 `scan_error`。
- BLE：可被搜到并连接（`connected result:0` 两次），断开（`disconnected reason:19`，为对端主动断开，正常）后自动重启广播、可重复连接。
- 范围：仅做扫描与广播，不连 AP、不配网、不激活云；联网能力在后续配网/BLE HID 阶段验证。

## 三、ws2812 问题详解（Step 5，不通过）

链路：`P13 → SN74LV1T34 (U2) → R3 → LED1 → LED2 → LED3`（3 颗菊花链）。

### 已尝试的方案
WS2812 需单线 NRZ 波形：每位约 1.25µs，时序容差约 ±150ns（T0H≈0.31µs、T1H≈0.62µs）。
本板数据脚是 **P13，而 P13 在 T5 上没有 SPI MOSI 路由**，无法使用 TuyaOpen 基于 SPI 的 WS2812 驱动。
因此 bring-up 固件采用 GPIO 位拆（bit-banging）+ 数 CPU 周期：

- 直接写 AON GPIO 寄存器（安全基址 0x44000400，值 2/0 = 高/低），因为 TAL 函数调用开销跟不上 800kHz 波形。
- 用 DWT 周期计数器卡亚微秒级高/低延时，传输期间关中断。
- CPU1 电源管理投票锁 120MHz（平台开机后会把共享时钟降到 60MHz），并运行时用 AON RTC 实测 CPU 频率、按实测频率换算波形。

经多轮迭代（驱动版本至 `gpio-dwt-autoclock-v5`），修掉了总线错误崩溃（写错非安全 GPIO 别名）和降频问题，固件已能正常运行并在 UART0 输出各图案帧。

### 结果与结论
固件能跑、能报每个图案，但 LED **无法稳定复现预期序列**（颜色错乱/闪烁/无法锁存）。
这是位拆的典型失败模式：即便关中断 + 数周期，T5 双核 + 电源管理环境仍无法持续保证纳秒级时序窗口。
**本版 PCB 上软件修不好**——数据脚必须换到硬件 SPI MOSI，由外设生成波形。判为硬件问题，非固件缺陷。

## 四、硬件改进说明（下一版改板）

### 缺陷 1：FPC1 脚序镜像（对应 Step 4）
- 底层 FPC1 封装脚序镜像（Pin1↔Pin18），底层放置未做脚序镜像，网表逻辑正确。
- v1.0 临时办法：反向插入排线抵消镜像。
- **改板要求**：修正 FPC1 封装脚序；正式固件 LCD 初始化沿用 INVOFF（no-inversion）序列。

### 缺陷 2：WS2812 数据脚在 P13（对应 Step 5）

根因：WS2812 数据网 `WS_DIN_5V`（经 U2/SN74LV1T34 与 R3）由 P13 驱动，而 P13 无 SPI MOSI 路由，
只能 GPIO 位拆，时序保证不了。

改法：改用 TuyaOpen 官方 SPI WS2812 驱动（每个 WS2812 位编成 8 个 SPI 位 @6.5MHz：0=0xC0、1=0xF0），
波形由 SPI 外设硬件产生，不受 CPU/中断抖动影响。据 SDK 核实（见文末"SDK 依据"），该驱动是
SPI master 单向写（只调 `tkl_spi_send`），WS2812 不需要 MISO/CSN/SCK 参与数据。

**定案：双改方案（WS2812 → P4 / SPI1，LCD_BL → P8）。**

为什么不是 SPI0 备用组（P46）：SPI0 已被 LCD 主组（P14–P17）实占，若 WS2812 也走 SPI0 备用组（P46），
是与 LCD **复用同一个 SPI0 控制器**，需固件分时切换引脚组、刷屏刷灯互相打断。改走 SPI1 可拿到
**独立**控制器，与 LCD 完全并行，且把 SPI0 备用组 P44–P47 完整留给二期（本板唯一还成整组的 SPI 资源）。

关键约束（SDK 核实得到）：T5 的 `tkl_spi_init(SPI1)` 会**无条件把 SPI1 整组四脚 pinmux**
（SCK=P2 / CSN=P3 / MOSI=P4 / **MISO=P5**），没有"只配 MOSI 跳过 MISO"的分支。而 P5 当前正是 LCD_BL。
因此**必须把 LCD_BL 从 P5 移走**，SPI1 才能干净使用——这就是要同时改两处的原因。

选脚对照（依据 `hardware/pinmap/pinmap.md` + SDK `tkl_spi.c`）：

| 控制器 | 脚位组 | 本板状态 |
|--------|--------|---------|
| SPI0 主组 | P14/15/16/17 | LCD 占用 |
| SPI0 备用组 | P44/45/46/47（P46=MOSI，J1.8） | 空闲，留给二期 |
| SPI0 组 | P33–P36 | P33/P35 未引出，不可用 |
| **SPI1** | **P2/P3/P4/P5**（SCK/CSN/**MOSI=P4**/MISO） | **选它**：MOSI=P4(J2.20) 空闲；移走 LCD_BL 后 P5 让给 MISO 空转 |
| QSPI0 | P22/23 + P24–27 | 被 NAV/KEY 占满 |
| QSPI1 | P2–P7 | P5/6/7 被 LCD 占，不可用 |

改板要点：

1. **WS2812 数据源：P13 → P4（SPI1_MOSI，J2.20）**。SDK 里 `TKL_SPI1_MOSI_PIN = GPIO_4`，选脚零改动。
2. **LCD 背光 BL：P5 → P8（J1.16，纯空闲 GPIO，高有效）**。背光是本板自搭的低边开关电路
   `BL → R2 → Q1(S8050) → R1 → LCD_LEDK`，只是个开关信号，换输入脚即可，屏侧（FPC LEDA/LEDK）不动。
   P8 在 J1、离 LCD 其它信号近，走线顺；也可选 P18/P19/P34/P36，但避开任何 SPI/QSPI 组脚。
3. 后段链路不变：P4(MOSI) → SN74LV1T34（U2，3.3→5V）→ R3 串阻 → LED1→LED2→LED3；每颗 100nF 就近去耦保留。
4. SPI1 只用 MOSI 一根线送数据；SCK(P2)/CSN(P3)/MISO(P5) 对 WS2812 无用，可不接/空转。
5. P13 释放为备用 GPIO；新 MOSI(P4) 走线短、远离 LCD SPI 线抑制串扰（5V 侧已有 R3 阻尼）。
6. 固件：弃用位拆驱动，改用官方 `tdd_pixel_ws2812` + SPI1 端口，去掉 CPU 投票、DWT 计时、关中断窗口。
7. 布线前在 EDA 里再核对 P4/P8 确无其它连接（两脚现均标空闲）。

> 该缺陷是 v1.0 数据脚选型限制，与 Step 4 的 FPC1 镜像缺陷相互独立，下一版一并修正。

#### SDK 依据（TuyaOpen，2026-08-31 核实）
- 官方 SPI WS2812 驱动：`src/peripherals/leds_pixel/tdd_leds_pixel/src/tdd_pixel_ws2812.c`
  —— `TUYA_SPI_ROLE_MASTER`，6.5MHz，0=0xC0/1=0xF0，仅 `tkl_spi_send` 单向写，无需 MISO。
- 引脚定义：`platform/T5AI/tuyaos/tuyaos_adapter/src/driver/tkl_spi.c`
  —— `TKL_SPI1_MOSI_PIN = GPIO_4`；`TKL_SPI0_G2_MOSI_PIN = GPIO_46`。
- 整组 pinmux：同文件宏 `TKL_SPI_SET_PIN(id)` 在 `spi_init_gpio` 中对整组四脚（含 MISO）无条件
  `gpio_dev_map`，故 SPI1 初始化必然占用 P5 → LCD_BL 必须让位。

### 非阻塞项（原理图/PCB 审核已记）
- 电池开关 SK12D07VG5 额定 0.3A，整机全白峰值可能触及。缓解：固件限 WS2812 亮度（已做）或换 0.5–1A 开关。
- 同一时间仅接一节电池（并联倒灌，不安全）。

## 五、结论

固件侧六个 bring-up 应用均可构建，唯一被硬件卡住的是位拆版 ws2812；其余全部台面验证通过。
硬件侧本版发现两个设计缺陷，均有明确改板方案，其余电路工作正常：
- FPC1 脚序镜像 → 下一版修正 footprint 脚序；
- WS2812 数据脚在无 SPI 路由的 P13 → 双改：WS2812 数据源换到 P4(SPI1_MOSI)、LCD_BL 从 P5 移到 P8，
  改用官方 SPI WS2812 驱动（SPI1 独立于 LCD 的 SPI0，且保留 SPI0 备用组给二期）。
