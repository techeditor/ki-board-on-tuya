## 0. 一页速览（Executive Summary）

- **做了什么**：从零定义一款"面向 Kiro 的 AI 小键盘"，完成产品需求（PRD v1.4）、
  引脚映射、网表、BOM、原理图、PCB v1.0，**PCB 已下厂加工**。

  文档撰写、器件选型比价、**通过 EasyEDA MCP 直接读写原理图/PCB**、双路交叉验证审核、文档与实物一致性对齐。

- **关键产出**：一套**自洽、可追溯、与 EDA 实物对齐**的硬件设计文档体系 + 已加工 PCB。

## 1. 产品设计：从想法到规格

### 1.1 产品定位
一款便携 AI 小键盘外设，**专为提升 Kiro CLI/IDE 的 agentic coding 体验**而设计。
不是通用键盘，而是面向"人 ↔ AI Agent 协作编程"工作流的专用输入 + 状态显示设备。

### 1.2 两个核心差异化
| 差异点 | 说明 |
|-------|------|
| **语音输入直达 Kiro** | 按键触发语音 → 识别文本自动注入当前聚焦的 Kiro 窗口，免切换、免打字 |
| **Agent 状态上屏** | Kiro CLI hook 把 Agent 的 Idle/Running/Error 状态实时显示在设备 LCD 上 |

### 1.3 产品形态
桌面小盒子：正面 2.8" LCD + 5 个机械键 + 1 个 5 向摇杆，锂电池供电，USB 或 BLE 连 PC，
3D 打印外壳。

### 1.4 分阶段交付（每阶段独立可演示）
- **阶段 0**：脚手架与硬件定义（本次总结范围）✅
- **阶段 1**：有线 MVP（串口 + Tauri 上位机 + Windows 系统 ASR）
- **阶段 2**：无线化（BLE GATT + 板端唤醒词 + 在线 ASR）
- **阶段 3**：BLE HID 直连 + 可选板端本地 ASR

## 2. 系统硬件设计：工作内容

### 2.1 硬件架构（路线 A：成品开发板 + 自制扩展底板）
- **主控**：T5AI-Core 开发板（T5-E1 模组，M33F@480MHz，8MB Flash/16MB RAM，Wi-Fi + BLE5.4）——**不改板**。
- **扩展底板**（本项目设计范围）：经 44P 排针插到开发板，承载：
  - 5× 机械键（CPG151101D06 茶轴，直焊）+ 1× 5 向摇杆（WS-1002）
  - 2.8" LCD（CL28CK230-18A，ST7789）+ 18P 0.5mm FPC 座
  - Type-C + CH340C（USB→UART，可烧录+通信）+ 自动复位电路
  - 锂电池并联座 + 电池总开关 + 2 颗电源指示灯
  - 3× WS2812（经电平转换）+ 上拉/限流/去耦/ESD
- **关键设计原则**：充电管理/音频/麦克风**由开发板负担**，扩展底板不重复设计。

## 2.5 会话跨度与工作量（真实记录）

本阶段工作**并非在单次会话中完成**，而是横跨 **多个 Kiro CLI 会话**（2026-08-21 → 08-24，约 4 天）：

- **6 个主会话**（承载对话正文，最大单个约 19MB / 17MB 记录），分别聚焦：
  仓库脚手架 → 引脚映射/网表/BOM → 原理图绘制（EasyEDA MCP）→ 原理图审核 →
  PCB 设计与审核 → 文档一致性对齐与收尾。
- **7 个子代理（subagent）会话**：Agent 在处理复杂子任务时派生的并行/隔离会话。
- Kiro CLI **按目录自动保存每一次对话**（`~/.kiro/sessions/cli/`），使跨会话的工作可追溯、可恢复。

> 对分享的意义：这体现了 Agent 辅助设计的**持续协作**特性——工作在多次会话中接力推进，
> 而**成果沉淀在项目文件（文档/网表/审核报告/session.md）中形成单一真值**，
> 不依赖某一次会话的上下文。文档即记忆。

## 3. 工作模式：Agent 驱动的软硬件协同设计

### 3.1 总体模式
```
知识库(tuya-kb) + datasheet ──┐
                               ├──> Kiro CLI (Agent) ──> 文档 / 网表 / BOM
产品需求 & 设计决策 ──────────┘         │
                                        ├──> EasyEDA MCP ──> 原理图 / PCB (直接操作)
                                        │
                                        └──> 代码化审核(网表提取+几何取证+DRC) ──> 审核报告
```

### 3.2 五种典型工作流
1. **规格撰写**：Agent 基于知识库 + datasheet 起草 PRD/引脚表/网表，人审校决策。
2. **器件选型**：Agent 查立创商城实时价 + 淘宝比价 + 对照本地库存，产出采购建议。
3. **EDA 绘图**：Agent 通过 MCP 在 EasyEDA 里**放器件、连线、改属性**（原理图）。
4. **代码化审核**：Agent 用脚本从 EDA **实时提取网表 + 几何坐标**做双路交叉验证。
5. **一致性对齐**：Agent **只读 EDA 实物**反向核对文档，修正不一致（不改 EDA）。

### 3.3 人机分工
- **人（开发者）**：定产品方向、拍板设计决策（电源方案、连接方式、选型）、手工微调 EDA 布局、最终审核。
- **Agent**：信息收集与核实、文档撰写与维护、EDA 批量操作、代码化审核、一致性检查、踩坑记录。

## 4. Agent / Kiro-CLI 主要做了什么 + 带来的优势

### 4.1 主要动作
| 领域 | Agent 做的事 |
|------|-------------|
| 文档 | 撰写并持续维护 PRD、引脚表、网表、BOM、审核报告、指南（中文优先，含变更记录） |
| 核实 | 逐脚核对 44P 排针 / 18P FPC / 摇杆脚序（对照官方 SCH PDF + 器件规格书） |
| 选型 | 立创实时比价 + 库存对照，定型茶轴 D06/FPC 座/CH340C/LDO 等，"基本零采购" |
| 绘图 | 经 EasyEDA MCP 放置 31+ 器件、连线、改容值、换真实封装（摇杆/母排） |
| 审核 | 网表提取（union-find 合并结点）+ 截屏放大取证，双路交叉验证原理图 |
| PCB | 只读提取线宽/过孔/铺铜/母排中心距，跑 DRC，核对 PRD 检查清单 |
| 对齐 | 发现并修正"文档 vs EDA"不一致（2 颗指示灯漏记、位号系统性错位） |
| 工程 | 清理临时文件、归档、`.gitignore` 补充、Git LFS 提交排障 |

### 4.2 带来的优势
- **信息密度高、可追溯**：每个结论都标注来源（datasheet 页码、官方 SCH、实测坐标、核实日期）。
- **审核用"证据"而非"印象"**：从 EDA 实时提取网表/几何做交叉验证，比肉眼看图更可靠。
- **一致性可机检**：`check_pins.py` 自动查引脚冲突；DRC 只读跑；文档与 EDA 用脚本对齐。
- **知识沉淀**：踩坑与经验实时写入 `session.md`，形成可复用的操作手册。
- **迭代快**：选型比价、文档重构、多份文档联动更新，分钟级完成。

## 5. 工作亮点与收获

### 5.1 亮点
1. **Agent 真正"动手"操作 EDA**：不是给建议，而是通过 MCP 直接画原理图、读 PCB、跑 DRC。
2. **代码化电路审核（双路交叉验证）**：
   - 路径 A：脚本从 EDA 实时提取网表（44 器件/196 引脚/84 网络）
   - 路径 B：官方导出 PNG/SVG + Playwright 放大取证
   - 以官方 PNG 为权威裁决，几何提取在密集区做 tol 校正
3. **母排可插合性用实测数据验证**：从 PCB 焊盘算出两排中心距 **25.476mm** vs 要求 25.502mm，
   偏差仅 26µm → 用数据确认"能插上"。
4. **敢于自我更正**：PCB 审核初版误判"5 颗 WS2812"，复核发现是 **3 颗 WS2812 + 2 颗普通指示灯**，
   并在报告中留下更正声明（可追溯，不掩盖）。
5. **源码级可行性核实**：USB HID 是否可行、云 ASR 激活链路（MQTT bind 免 App）等，
   都追到 TuyaOpen 源码/官方文档层面下结论，而非猜测。

### 5.2 收获（可复制的方法论）
- **datasheet/规格书 > 既有文档**：CL28CK230 的 18P 脚序曾在文档里记错（1=RST），
  以实物规格书（PAGE7）纠正为 1=GND。**核对硬件先读 datasheet。**
- **审核要有"权威裁决源"**：几何提取会因密集区容差失真，需用官方导出图做最终裁决。
- **"照抄官方参考设计"是低风险策略**：CH340C 自动复位电路照抄开发板 CH342F 方案，
  避免自创拓扑的风险（也纠正了审核中"发射极未接地=错误"的误判——实为官方有意设计）。
- **文档要标注不确定性**：读不到的实际阻值，据实标注"以 EDA 原理图为准"，**不臆测**。

## 6. 遇到的问题/坑与解决办法

### 6.1 硬件设计层面
| 问题 | 解决 |
|------|------|
| T5 无 USB Device HID（SDK 仅 Host） | "直连"改走 BLE HID（BLE5.4 原生），二期实现 |
| P28/P33/P35 未从 44P 排针引出 | 改用已引出的 GPIO；`check_pins.py` 校验无冲突 |
| 库存青轴 D91 无立创现货 | 改定 D06 茶轴（现货、更适合桌面小设备） |
| LCD 18P 脚序文档记错（1=RST） | 以规格书纠正为 1=GND，全链路重连 |
| 电池开关 SK12D07VG5 额定 0.3A 可能不够 | 固件限 WS2812 亮度，或换更高额定开关（已记录为待办） |
| 两个 Type-C / 两节电池并联风险 | 丝印强约束"只插一个/一节"；文档多处标注 |

### 6.2 EasyEDA MCP 操作层面（session.md 沉淀）
| 坑 | 解决/规避 |
|----|----------|
| **手动导线不随器件移动** | 器件位置定稿后再连线；移动后必须重连该器件所有脚 |
| 连接核查用旧坐标会错判 | 用**当前实时坐标** + 电源/地符号(NetFlag)解析，导线 net 为空时追踪端点 |
| 坐标单位混淆（PCB=1mil，原理图=0.01inch） | 严格区分，用错会偏 10× |
| 枚举用裸数字出错 | 用枚举成员（如 `EPCB_LayerId.TOP`） |
| 忘记 `await` 拿到 Promise | 所有 API 必须 await |
| 阻容实际值 API 读不到（属性引用未解析） | 不臆测，标注"以 EDA 为准" |

### 6.3 环境/工具链层面（Windows）
| 坑 | 解决 |
|----|------|
| SKILL.md 的 bash 命令在 Windows 跑不通 | 改用 PowerShell 等价写法 / `exec.mjs` 探活 |
| PowerShell 后台起 bridge 常失败、吞输出 | 用 detached 子进程 launcher（`launch_bridge.mjs`）+ `child.unref()` |
| PowerShell 多行输出被截断（误判文件内容） | 用 git 原生命令 / `-c core.quotepath=false` 交叉核对 |
| **Git LFS 推送被拒**（pre-receive hook declined） | GitDefender 占用 hooks 目录致 LFS 钩子装不上 → 手动 `git lfs push --all origin main` 再 `git push` |

### 6.4 Agent / Kiro-CLI 的不足（客观记录）
1. **长输出会被 shell 截断**：PowerShell 回显多行时可能只看到首行，一度误判 `.gitattributes`
   规则丢失。→ 需交叉验证、分批取数。
2. **对复杂对象序列化不稳**：EDA 返回含中文/大对象时偶发空响应，需简化 payload、拆批、
   服务端 join 成纯文本。
3. **会自我误判**：如"5 颗 WS2812""WS2812 缺串阻""发射极未接地=错误"——**都靠复核纠正**，
   说明**单次结论需二次验证**，不能全信。
4. **读不到属性实值**：原理图阻值是属性引用，API 拿到占位符，无法直接读出实际阻值。
5. **环境相关命令需适配**：SKILL/文档里的示例多为 Linux/bash，Windows 下要人工转译。
6. **依赖外部工具状态**：EDA 窗口关闭/刷新会断链、windowId 会变，需重连与重新选窗。

> 结论：Agent 在**信息处理、批量操作、代码化审核**上大幅提效，但**关键工程结论必须复核**，
> Agent 的价值在于"把证据摆出来"，最终判断仍需人把关。

## 9. 给后续 / 同类项目的建议（Takeaways）

1. **用 Agent 做硬件设计的文档与审核，收益最大**——尤其"代码化审核"（网表+几何取证）远超肉眼看图。
2. **让 Agent 操作 EDA 是可行的**，但要建立"操作手册"（如 session.md）沉淀工具坑，避免重复踩。
3. **建立单一真值源**：本项目以 EDA 实物为真值，文档反向对齐——避免"文档和实物各说各话"。
4. **关键结论必须复核**：Agent 会自信地给出错误结论，价值在于"摆证据"，人做最终裁决。
5. **datasheet 优先、照抄官方参考设计**：低风险、可追溯。
6. **文档标注来源与不确定性**：可追溯 + 不臆测，是长期可维护的关键。
