# 硬件设计 — 引脚映射与连接方案（Task 2）

> 路线：**T5AI-Core 成品开发板** 通过 44P 排针插到**自制扩展底板 PCB** 上。
> 扩展底板只承载：5× 机械键 + 1× 5向摇杆 + LCD 的 18P FPC 座 + 3× WS2812 RGB LED（含电平转换）
> + Type-C(USB-转-UART，CH340C，可烧录+通信；VBUS 经 LDO 仅供 CH340C，不供系统)
> + 锂电池并联座(带电池总开关) + 上拉/限流/ESD/去耦 + 2×1×22 母排座。
> 电源管理（充电 ETA6003）、音频、麦克风由开发板负担，扩展底板不重复设计。
>
> 权威依据：涂鸦官方 Pinmux 表、T5AI-Core 概览、chatbot demo 板级驱动 `tuya_t5ai_core.c`。

## 1. 能力与连接方式映射（需求对照）

| 需求能力 | 实现方式 | 承载硬件 | 优先级 |
|---------|---------|---------|--------|
| PC连接①：USB串口+助手 | T5 UART0(P10/P11) ↔ 板载 CH343 串口桥 ↔ Type-C ↔ PC COM | 开发板 | 高（一期） |
| PC连接②：BLE自定义GATT+助手 | T5 BLE5.4 GATT | 开发板（模组） | 高（一期） |
| PC连接③：BLE HID | NimBLE 手搓 HID(0x1812)+SM配对+字符→HID键值 | 开发板（模组） | 中（二期） |
| 语音①：板载MIC→云ASR | 板载模拟MIC+codec(AEC,16K/16bit) | 开发板 | 高（需配网） |
| 语音②：PC收声→本机/3P ASR | PC麦克风，助手侧ASR | PC | 高（无需配网） |
| 语音③：板载MIC→传PC→PC ASR | MIC采集经UART/BLE传PC | 开发板 | 中（二期） |
| WiFi配网①：BLE配网 | 官方默认BLE配网 | 开发板 | — |
| WiFi配网②：USB+助手配网 | 助手经串口下发配网信息 | 开发板+助手 | — |

> 无配网时仅支持语音②③（本地/PC 侧 ASR），语音①（云 ASR）不可用。

## 3. LCD 连接（沿用官方接线，固件零改动）

CL28CK230-18A 为 ST7789 驱动 SPI 屏。**直接采用涂鸦官方 EVB/Core 的 ST7789 接线**，
TuyaOpen chatbot demo 现成，固件仅需把分辨率改为 320×240。

| 功能 | T5 引脚 | 说明 |
|------|--------|------|
| SPI 时钟 | P14 (SPI0_SCK) | 硬件 SPI0，48 MHz |
| SPI 数据 | P16 (SPI0_MOSI) | 单向写 |
| 片选 CS | P15 | |
| 数据/命令 DC | P17 | |
| 复位 RST | P6 | |
| 背光 BL | P8 | GPIO 高有效（v1.2：P5→P8, J2.16/PWM2） |
| 屏电源 PWR | P7 | GPIO 高有效 |

固件侧关键宏（`tuya_t5ai_core.c`，仅列改动）：
```c
#define BOARD_LCD_WIDTH   240   // CL28CK230: 保持 240（短边）
#define BOARD_LCD_HEIGHT  320   // CL28CK230: 由 240 改为 320（长边）
#define BOARD_LCD_PIXELS_FMT TUYA_PIXEL_FMT_RGB565
#define BOARD_LCD_SPI_CLK 48000000
// CS=P15 DC=P17 RST=P6 BL=P8(v1.2) PWR=P7 均沿用官方（BL 从 P5 移到 P8）
```

> ⚠️ **已确认**：CL28CK230-18A 的 18P FPC 逐脚定义（来自 `datasheets/CL28CK230-18A.../接线图.pdf`）。
> ℹ️ **SPI0 引脚说明**：官方 SPI0 默认组 = P15/P14/P16/**P17**（CS/SCK/MOSI/**MISO**）。本设计 LCD 只写不读，
> **不使用 MISO**，官方板级驱动把 **P17 复用为普通 GPIO 作 LCD_DC**（数据/命令），这是官方接线本身的做法，
> 与 SPI0 单向写屏不冲突（MISO 脚位让给 DC）。

### 18P FPC 逐脚定义（0.5mm，4线SPI + 电阻触摸 RTP）

| FPC Pin | 信号 | 接到（T5 / 处理） |
|---------|------|------------------|
| 1 | GND | GND |
| 2 | RST | P6（LCD_RST） |
| 3 | SCL | P14（SPI0_SCK） |
| 4 | RS（DC） | P17（LCD_DC） |
| 5 | CS | P15（SPI0_CS） |
| 6 | SDA（MOSI） | P16（SPI0_MOSI） |
| 7 | SDO | 不接（单向写屏，留空） |
| 8 | GND | GND |
| 9 | VCC | **3.3V**（屏电源，规格书 2.8–3.3V；就近去耦） |
| 10 | LEDA | 背光阳极 → **直接接 3.3V** |
| 11 | LEDK1 | 背光阴极（4 路并联=K）→ **经限流电阻 R6 到 GND** |
| 12 | LEDK2 | 背光阴极 → K（同上） |
| 13 | LEDK3 | 背光阴极 → K（同上） |
| 14 | LEDK4 | 背光阴极 → K（同上） |
| 15 | XL (X-) | 电阻触摸 X-（一期不用，留空/预留） |
| 16 | YU (Y-) | 触摸 Y-（预留） |
| 17 | XR (X+) | 触摸 X+（预留） |
| 18 | YD (Y+) | 触摸 Y+（预留） |

- 屏为 **4线SPI + 电阻触摸(RTP)**，驱动 IC **ST7789V**，供电 **2.8–3.3V**。本项目一期不启用触摸，15-18 预留。
- **背光（依规格书/接线图，共阴 4 颗白光 LED 并联，限流在阴极侧）**：
  **LEDA(10) → 直接接 3.3V**；**LEDK1-4(11-14) 并联=K → 限流电阻 R6 → GND**。
  即回路 `3.3V → LEDA →〔屏内 4 LED〕→ K → R6 → GND`。
  VLED=2.9–3.3V typ 3.1V、电流 80–100mA。R6=**4.3Ω**（对齐接线图 4R33），可按实际亮度调。
  ⚠️ 限流电阻在 **LEDK 阴极侧**（不是 LEDA 侧）——接线图 R1(4R33) 串在 K 与地之间。
- ⚠️ **脚序更正（2026-08-22）**：经规格书 `CL28CK230-18A_SPEC_V0` PAGE 7 与接线图核实，
  正确脚序为 **1=GND**（此前文档误记为 1=RST，整体错位一位），已按实物规格修正。

## 4. 输入分配（5 机械键 + 5 向摇杆）

全部为**数字输入，内部上拉，按下接地（低有效）**，去抖在固件侧处理。
避开所有已占用引脚，选纯 GPIO。
> ✅ **二期总线可用性（v1.2 定案）**：官方 **SPI1 = P2/P3/P4/P5**（CS/SCK/MOSI/MISO）。v1.2 已把
> **LCD_BL 从 P5 移到 P8**，P5 让位给 SPI1_MISO，故 **SPI1（P2/P3/P4/P5）整组可完整使用**（本项目即用其 MOSI=P4 驱动 WS2812）。
> **QSPI1(P2-P7)** 仍因 P6/P7 被 LCD（RST/PWR）占用而不可用。若二期需要额外 SPI，也可改用 **SPI0 的备用组 P44-P47**
> （这几脚在 J1 空闲引出）。UART2(P31/P30 或 P41/P40)、I2C 组不受影响。
>
> 📜 **历史（v1.0，已废弃）**：v1.0 时 P5=LCD_BL，曾判定"SPI1 缺 MISO 只能做无 MISO 的 3 线只写(P2/P3/P4)"。
> 该限制随 v1.2 把 LCD_BL 移到 P8 后已解除。P5 只是本板背光**可改**控制脚（低边开关 Q1，非物理占死），故可让位。
> WS2812 改板即采用此方案：**数据源 P13 → P4（SPI1_MOSI）**，用官方 SPI WS2812 驱动（独立于 LCD 的 SPI0）。
> 注意 SDK `tkl_spi_init(SPI1)` 会**整组 pinmux 含 MISO=P5**（`tkl_spi.c` 宏 `TKL_SPI_SET_PIN`），
> 故 P5 必须先让位，这也是"WS2812→P4 + LCD_BL→P8"双改缺一不可的原因。
> 详见 `firmware/bringup/测试总结.md` 第四节。

### 5 向摇杆（WS-1002，4方向+中心，公共端接 GND）

WS-1002 为 6 脚（脚序已确认，来自规格书电路图）：
① A方向 · ② Center · ③ B方向 · ④ D方向 · ⑤ Com（公共，接 GND） · ⑥ C方向
内部两组共 Com：①A/②Center/③B 与 ④D/⑤Com/⑥C。⑤ 为公共端接 GND，其余 5 脚各接一个 GPIO。
底面丝印：①②③ 一排、④⑤⑥ 一排；4 个方向对应四斜角，Center 为垂直按下。

> 方向命名（A/B/C/D）对应物理斜角，映射到 UP/DOWN/LEFT/RIGHT 由固件按外壳装配方向定义，
> 下表以逻辑方向给出（实际 A/B/C/D↔上下左右在装配后标定）。

| 逻辑名 | 摇杆脚 | T5 引脚 | 排针位置 | 备注 |
|--------|-------|--------|---------|------|
| NAV_A (→UP)     | ① | P32 | J2.14 | GPIO/中断 |
| NAV_B (→DOWN)   | ③ | P20 | J2.4  | GPIO/中断 |
| NAV_C (→LEFT)   | ⑥ | P21 | J2.5  | GPIO/中断 |
| NAV_D (→RIGHT)  | ④ | P22 | J2.6  | GPIO/中断 |
| NAV_CENTER      | ② | P30 | J2.11 | GPIO/中断 |
| Com             | ⑤ | GND | J1/J2 GND | 公共端 |

> 原 P33/P35/P34/P36 中 P33/P35 未从排针引出，已改用 P20/P21/P22/P30（均 J2 引出）。
> 排针其余可用空闲 GPIO（微调备用）：P44/P45/P46/P47/P19/P18/P13/P12(J1)、P31(J2)。
> （v1.2：P4=WS2812_DIN、P8=LCD_BL 已占用；P2/P3/P5 保留给 SPI1 组；P13 因 WS2812 迁到 P4 而释放为空闲）

## 6. 电路细节（扩展底板 PCB）

### 6.1 按键与摇杆
- 每个输入使用 T5 **内部上拉**，按下接 GND → 低有效。为抗干扰/静电，可选每脚外加
  100nF 到 GND 做硬件去抖（可选，固件已有去抖）。
- 若走线较长或外壳金属化，建议每个输入脚串 100Ω 限流 + 对地 TVS/ESD（见 BOM）。
- 摇杆公共端接 GND；机械键一端接对应 GPIO、一端接 GND。
- **机械键轴体直焊到 PCB**（CPG151101 两脚，非热插拔轴座）；PCB 按 CPG151101 直插焊盘布局。

### 6.2 LCD FPC
- 18P 0.5mm FPC 座（下接/翻盖式），逐脚连到 44P 母排对应的 T5 引脚（§3）。
- 背光：CL28CK230 若为内置 LED 驱动/需限流，按规格书在 BL 路串限流电阻或走 PWR_ON 使能；
  官方 demo 用 GPIO(P5) 直接开关背光。**逐脚细节待规格书确认**。
- SPI 数据线（SCK/MOSI）可选串 22-33Ω 阻尼电阻抑制振铃（高速 48MHz 时建议）。
- FPC 电源脚就近加去耦：1µF + 100nF 到 GND。

### 6.3 44P 母排座
- **2× 1×22 2.54mm 排母**（不能用 1×44！两排分列开发板两条长边，中心距=25.502mm 实测）。
  - J1（左边）= 22pin：3V3/RST/P20-P32/P3-P8/P5-P7/5V/GND
  - J2（右边）= 22pin：GND/TX/RX/P34-P47/P19-P12/P2/DP/DN/GND
  - 底板上两个排母中心距 = **25.502mm（卡尺实测，2026-08-21）**
- 母排把开发板的 3.3V / 5V / GND / 各信号引到扩展底板。
- LCD 与输入器件由排母的 3.3V 供电（数字域）。

### 6.4 ESD/保护
- USB、对外可触摸的金属/接插处加 ESD 阵列。
- 输入脚可选 LESD5D5.0（库存有）做 ESD 防护。

### 6.5 扩展板 Type-C + USB-转-UART（CH340C）——可烧录 + 通信

> 背景：**T5 无 USB Device 能力**（SDK 无 device/CDC/HID 栈，已源码核实）。PC 侧的"USB 串口"由
> **USB-转-UART 桥接芯片**提供。最终产品外壳只露出扩展板 Type-C，故扩展板必须能**烧录 + 通信**。

- **Type-C 母座** → **CH340C（SOP-16，库存有）** USB-转-UART 桥：
  - CH340C USB(D+/D-) ← Type-C 的 D+/D-（USB2.0 全速；Type-C 需 CC1/CC2 各接 5.1kΩ 下拉做 UFP/设备角色）
  - ⚠️ **USB 隔离**：Type-C 的 D+/D- **只接 CH340C**，**不接**排针 J2 上的 **DP/DN**（开发板 T5 的 USB Host 信号，另一套 USB）。扩展板不引出/不使用排针 DP/DN。
  - CH340C 串口(TXD/RXD) → **T5 UART0（P10/P11，排针 J2）**
- **与开发板板载 CH342F 共用 UART0**：两颗 USB-UART 桥并在 P10/P11 上。
  **规则：同一时间只插一个 Type-C**（最终产品插扩展板口；开发调试可拆壳用开发板口）。
- **TX 隔离**：CH340C 的 TXD → T5 RX(P10) 之间**串 2kΩ 电阻**（库存 C60488），降低与开发板 CH342F 的总线争用风险。460800 烧录下 RC 影响可忽略（<1.5%）。
- **自动复位/下载电路**（照抄开发板 SCH，U2 CH342F 区的 Q2 S8050 单管方案）：
  - **RTS0 → Q2(S8050) 基极**（直连）
  - **DTR0 → R22(4.7kΩ) → Q2 基极**（汇入同一基极节点）
  - **Q2 集电极 → R14(100Ω) → T5_RST（排针 J2.2）**；**Q2 发射极 → GND**
  - T5_RST 上拉 **R47(10kΩ)→3V3** + 去耦 **C51(0.1µF)**：**开发板已有**（在 J2.2 处），扩展板可不重复
  - 元件对应：Q_RST=S8050、R_DTR=4.7kΩ、R_RST=100Ω
  - 使 `tos.py flash` / TyuTool 能自动进 bootloader 下载模式，一键烧录，无需手动按复位
- **烧录 vs 通信如何区分**（同一 UART0 分时复用）：
  1. 复位时有下载工具握手 → 进 bootloader（烧录）；正常启动 → 应用固件（通信）
  2. PC 端串口独占：烧录时 TyuTool 占 COM，通信时 Companion 占 COM，互斥
  3. 无需硬件开关，切换 = 关一个软件开另一个
- CH340C 外围：VCC 去耦 100nF+1µF；**V3 脚与 VCC 短接**（3.3V 供电时的标准接法，非接电容）；USB 线串 ESD。
- **CH340C 供电（关键）**：由**扩展板 Type-C 的 VBUS(5V) → 小 LDO(HE9073A33M5R, SOT-23-5, 3.3V, 库存有) → CH340C VCC=3.3V**。
  - 只喂 CH340C 一颗芯片，**不给系统灌电**（不接排针 5V，与"Type-C 不供电系统"一致）。
  - CH340C IO = 3.3V，**直接匹配 T5 UART，无超压风险**。
  - **不依赖电池/系统上电**：插 Type-C 即由 PC VBUS 供电 → 电池空了也能烧录/救砖（符合产品形态只用扩展板口）。
- **Type-C VBUS 不接系统**（方案1：Type-C 只做数据不供电系统）。系统供电靠电池 + 开发板 Type-C。

### 6.6 锂电池并联座

- 扩展板放一个 **JST PH 1.25mm 2P 电池座**，其 **BAT+/BAT-** 与开发板 JST 座（CN1）**并联到同一 BAT 网络**。
- 充电/放电管理仍由**开发板 ETA6003** 负责，扩展板**不做任何充电电路**。
- ⚠️ **安全规则：同一时间只插一节电池**（插开发板座 或 插扩展板座，不可两座各插一节——两节电池直接并联会互相倒灌，有危险）。
- **电池总开关 SW_BAT**：扩展板电池座 **BAT+ 串一个拨动开关（SK12D07VG5，立创 C431548，库存有）**作电池总开关。
  - 关断 = 切断本扩展板电池供电（关机）；**Type-C 插入时系统仍照常通电/充电**（开关只管电池路径，符合直觉）。
  - 语义 = "电池总开关"，非"真·总开关"（真总开关需切 ETA6003 输出，扩展板引不出，故不做）。
- 相当于把开发板电池座**引出**到扩展板更方便的位置，并加一个电池开关。

### 6.7 3× WS2812 RGB LED + 电平转换

- 3 颗 WS2812（库存款，见 BOM）**单线菊花链**：数据源 → LED1.DIN，LED1.DOUT → LED2.DIN → LED3.DIN，1 根数据线控 3 颗。
- 数据脚 **P4（排针 J2.20，SPI1_MOSI）**，输出（v1.2：由 P13 迁入）。用官方 **SPI WS2812 驱动**（波形由 SPI 外设产生，独立于 LCD 的 SPI0）。
  > ⚠️ v1.0 曾用 **P13（J1.16）GPIO 位拆**，因双核 + PM 下纳秒级时序不达标而放弃（见 `firmware/bringup/测试总结.md`）；P13 已释放为空闲/NC。
  > 注意 SDK `tkl_spi_init(SPI1)` 会整组 pinmux（含 MISO=P5），故 P5 必须先从 LCD_BL 让位（v1.2 已把 LCD_BL 移到 P8），SPI1 组 P2/P3/P4/P5 才可用。
- **电平转换**：T5 GPIO 是 3.3V，WS2812 用 **5V** 供电时 DIN 阈值可能不足 → 经
  **SN74LV1T34（SOT-23-5，单门 3.3→5V 电平转换，库存 C100024 有）**：P4(3.3V) → SN74LV1T34 → LED1.DIN(5V)。
- 供电：5V 取自排针 J1；每颗 LED 就近 **100nF** 去耦；DIN 线串 **100-330Ω** 抑制振铃。
- 电流：3 颗全白 ≈ 180mA，由开发板 5V 域供给。
