# Security Policy

## Supported versions

Security fixes are made for the current release only: the latest published
version of the firmware and the Companion (the newest release tag of this
repository). Older versions are not patched; please update first.

## Reporting a vulnerability

Report it privately through GitHub:

1. Open the main page of this repository.
2. Open the **Security** tab (GitHub may label it **Security and quality**).
3. Click **Report a vulnerability** and fill in the form.

GitHub describes the steps in
[Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).

Do **not** report a vulnerability in a public issue, pull request or discussion.
If you cannot find **Report a vulnerability**, open an issue that asks the
maintainers for a security contact, without any detail about the problem.

## What to include

- The affected part (firmware, Companion, protocol or documentation) and its version.
- A short description and the impact: what an attacker can do, and what they need (physical access, USB, Bluetooth range, a local account).
- Steps or a proof of concept that reproduces it.
- Test values only. Do not send real credentials, Tuya device UUIDs or AuthKeys, or other people's data.

We read every report and will keep you informed of the outcome, but we do not
promise a response time.
